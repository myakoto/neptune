# Neptune

Живой переводчик речи для созвонов под Windows (Rust).

Направления работы:
- **Мне говорят** — звук созвона (WASAPI loopback) → Deepgram → Yandex Translate → русские субтитры;
- **Я говорю** — push-to-talk с микрофона → распознанный русский → английский текст в буфере обмена.

Сейчас реализован первый вертикальный срез в виде CLI: перевод текста и
распознавание готового WAV-файла. Дальше: стриминговый клиент Deepgram,
захват звука, GUI-окно.

## Настройка

Пользователю: открыть ⚙ в окне приложения, вставить ключи, перезапустить —
они сохранятся в `%APPDATA%\neptune\.env`.

Разработчику: `cp .env.example .env` в корне проекта и заполнить ключи.
`.env` подхватывается слоями (приоритет сверху вниз): текущая директория →
директория exe → `%APPDATA%\neptune\.env`.

| Переменная | Откуда |
|---|---|
| `DEEPGRAM_API_KEY` | console.deepgram.com |
| `YANDEX_API_KEY` | API-ключ сервисного аккаунта Yandex Cloud с ролью `ai.translate.user` |

Release-сборка — чистое GUI-приложение без консоли (CLI-команды выводят
текст только в debug-сборке).

## Использование

```
cargo run -- translate "привет, как дела"        # ru -> en
cargo run -- translate --from en --to ru "hello"
cargo run -- transcribe path\to\audio.wav        # автоопределение языка
cargo run -- transcribe --language ru audio.wav
```

## Проверки качества

Всё обязано проходить перед коммитом:

```
cargo fmt --check                          # форматирование
cargo clippy --all-targets -- -D warnings  # линтер (pedantic включён в Cargo.toml)
cargo test                                 # тесты
```

Автоисправление форматирования: `cargo fmt`.

## Версии и релизы

Версия — semver, единственный источник правды — `version` в Cargo.toml.
Теги руками не ставим: их создаёт сам workflow
([pipeline.yml](.github/workflows/pipeline.yml)).

Один конвейер на все случаи:

- любой пуш и PR → `fmt` / `clippy` / `test`;
- пуш в master, где версия в Cargo.toml ещё не имеет тега → после зелёных
  проверок собирается exe, создаётся тег `vX.Y.Z` и публикуется Release.

Выпустить релиз:

1. Поднять `version` в Cargo.toml (например, `0.2.0`).
2. `git push origin master` — всё.

**`git tag` руками не делаем.** Тег создаёт workflow сам; ручной тег ничего
не ускорит, а раньше ещё и отменял публикацию.

Пуш без изменения версии просто гоняет проверки: релизная задача видит
уже опубликованный Release для этой версии и не запускается.

Бета: версия с суффиксом (`0.3.0-beta.1`) — Release помечается prerelease.
Автообновление такие версии **не** предлагает: приложение обновляется
только до последнего стабильного релиза.

### Автообновление

Приложение само узнаёт о новом релизе, само его скачивает и само
подменяет свой бинарник — вручную ничего скачивать не нужно.

- **Проверка**: при старте GUI (таймаут 15 секунд) и по кнопке `🔄` в шапке.
- **Предложение**: если релиз новее установленной версии — баннер
  «Доступна версия X» с выбором «⬇ обновиться / остаться на текущей».
- **Установка**: по подтверждении приложение скачивает бинарник из релиза,
  сверяет SHA-256 с файлом `.exe.sha256` из того же релиза и подменяет
  себя (`self_replace`: Windows не даёт перезаписать запущенный exe, поэтому
  старый переименовывается, новый встаёт на его место).
- **Перезапуск**: после установки приложение запускает новую версию само
  и закрывает текущее окно.
- **Целостность**: релиз без файла `.exe.sha256` не устанавливается —
  лучше не обновиться, чем поставить битый бинарник.

Вручную: `neptune update`.

Релиз публикует сам workflow: в нём лежат `neptune-x86_64-pc-windows-msvc.exe`
(его качает апдейтер), `.exe.sha256` (контрольная сумма) и `.zip`
(для ручной загрузки, если exe заблокирован политикой).

## Структура

```
src/
  main.rs           точка входа (минимальная)
  cli.rs            разбор аргументов, диспетчер команд
  config.rs         ключи API из .env / окружения
  translate/        перевод текста (Yandex Cloud Translate v2)
  stt/              распознавание речи (Deepgram Nova-3)
```

Правило: каждый модуль — одна зона ответственности, свои типы ошибок
(`thiserror`) и юнит-тесты рядом с кодом. Сетевые вызовы отделены от чистой
логики (сборка URL, разбор ответов) — тесты гоняются без сети.
